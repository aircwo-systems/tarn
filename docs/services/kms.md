# KMS

Symmetric encryption keys for Lambda functions, the AWS Encryption SDK and Terraform.

<span class="status-badge status-partial">Partial Support</span>

## Supported Operations

| Operation | Status | Notes |
|-----------|--------|-------|
| CreateKey | Supported | `SYMMETRIC_DEFAULT` encryption keys only |
| DescribeKey | Supported | |
| ListKeys | Supported | One page |
| UpdateKeyDescription | Supported | |
| EnableKey / DisableKey | Supported | Disabled keys refuse cryptographic operations |
| ScheduleKeyDeletion / CancelKeyDeletion | Supported | The key is removed once the 7–30 day window passes |
| CreateAlias / UpdateAlias / DeleteAlias / ListAliases | Supported | `alias/aws/*` keys are created on first use |
| TagResource / UntagResource / ListResourceTags | Supported | |
| GetKeyPolicy / PutKeyPolicy / ListKeyPolicies | Supported | Stored, not enforced |
| GetKeyRotationStatus / EnableKeyRotation / DisableKeyRotation | Supported | Stored; key material never rotates |
| Encrypt / Decrypt / ReEncrypt | Supported | Encryption context is enforced |
| GenerateDataKey / GenerateDataKeyWithoutPlaintext | Supported | |
| GenerateRandom | Supported | |

## Features

### Lambda functions

Functions reach KMS through the `AWS_ENDPOINT_URL` Tarn injects, so the AWS SDK and the AWS Encryption SDK work unchanged:

```javascript
import { KmsKeyringNode, buildClient, CommitmentPolicy } from '@aws-crypto/client-node';

const { decrypt } = buildClient(CommitmentPolicy.REQUIRE_ENCRYPT_ALLOW_DECRYPT);
const keyring = new KmsKeyringNode({ keyIds: [process.env.KEY_ARN] });

const { plaintext } = await decrypt(keyring, Buffer.from(ciphertext, 'base64'));
```

### Cognito custom senders

A user pool's `KMSKeyID` names the key that encrypts codes for `CustomEmailSender` and `CustomSMSSender` triggers. See [Custom sender triggers](/services/cognito#custom-sender-triggers).

### Keys

Key IDs resolve as a key ID, key ARN, alias name or alias ARN. ARNs must use Tarn's account and region. Each account has its own keys.

Key material is 256-bit AES, generated by Tarn and encrypted at rest with the [vault key](/guide/configuration#secrets-encryption) when one is configured. Ciphertext blobs use Tarn's own format: they decrypt only in the Tarn data directory that made them, under the same key and encryption context.

## Examples

### Using Terraform

```hcl
resource "aws_kms_key" "app" {
  description             = "App secrets"
  deletion_window_in_days = 7
}

resource "aws_kms_alias" "app" {
  name          = "alias/app"
  target_key_id = aws_kms_key.app.key_id
}
```

## Known Limitations

- No asymmetric, HMAC, multi-Region or imported keys, and no custom key stores
- No grants (`CreateGrant`, `ListGrants`, `RetireGrant`)
- Key policies and IAM are not evaluated
- Rotation is recorded but key material never changes
- `ListKeys`, `ListAliases` and `ListResourceTags` return everything in one page
