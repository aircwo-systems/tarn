## Examples

### Using AWS SDK

<div class="example-block">
<div class="lang">JavaScript</div>

```javascript
import { S3Client, CreateBucketCommand, PutObjectCommand, GetObjectCommand } from "@aws-sdk/client-s3";

const s3 = new S3Client({
  endpoint: "http://127.0.0.1:4566",
  region: "us-east-1",
  credentials: { accessKeyId: "test", secretAccessKey: "test" }
});

// Create bucket
await s3.send(new CreateBucketCommand({ Bucket: "my-bucket" }));

// Put object
await s3.send(new PutObjectCommand({
  Bucket: "my-bucket",
  Key: "file.txt",
  Body: "Hello World"
}));

// Get object
const obj = await s3.send(new GetObjectCommand({
  Bucket: "my-bucket",
  Key: "file.txt"
}));

console.log(await obj.Body?.transformToString());
```
</div>

### Bucket Configuration

<div class="example-block">
<div class="lang">JavaScript</div>

```javascript
import {
  PutBucketVersioningCommand,
  PutBucketEncryptionCommand,
  PutBucketCorsCommand,
  PutBucketLifecycleConfigurationCommand,
  PutPublicAccessBlockCommand,
} from "@aws-sdk/client-s3";

// Enable versioning
await s3.send(new PutBucketVersioningCommand({
  Bucket: "my-bucket",
  VersioningConfiguration: { Status: "Enabled" }
}));

// Server-side encryption
await s3.send(new PutBucketEncryptionCommand({
  Bucket: "my-bucket",
  ServerSideEncryptionConfiguration: {
    Rules: [{ ApplyServerSideEncryptionByDefault: { SSEAlgorithm: "AES256" } }]
  }
}));

// CORS
await s3.send(new PutBucketCorsCommand({
  Bucket: "my-bucket",
  CORSConfiguration: {
    CORSRules: [{ AllowedMethods: ["GET"], AllowedOrigins: ["*"] }]
  }
}));

// Lifecycle
await s3.send(new PutBucketLifecycleConfigurationCommand({
  Bucket: "my-bucket",
  LifecycleConfiguration: {
    Rules: [{
      ID: "expire-old",
      Status: "Enabled",
      Expiration: { Days: 90 },
      Filter: { Prefix: "logs/" }
    }]
  }
}));

// Block public access
await s3.send(new PutPublicAccessBlockCommand({
  Bucket: "my-bucket",
  PublicAccessBlockConfiguration: {
    BlockPublicAcls: true,
    BlockPublicPolicy: true,
    IgnorePublicAcls: true,
    RestrictPublicBuckets: true
  }
}));
```
</div>

## Access URL Format

S3 objects in Tarn use path-style URLs:

```
http://127.0.0.1:4566/_s3/{bucket}/{key}
```

Example:
```bash
curl http://127.0.0.1:4566/_s3/my-bucket/file.txt
```

## Additional Features

- Multipart uploads
- Bucket notification configuration for Lambda targets (prefix and suffix filters)
- `CreateBucket` parses `LocationConstraint` from the request body and rejects explicit `us-east-1` (matching real AWS behaviour). When no body is sent, the signing region from the `Authorization` header is used
- `HeadBucket` returns the stored region in the `x-amz-bucket-region` response header
- All bucket configuration (versioning, encryption, CORS, lifecycle, tags, policy, PAB, ownership controls, object lock, logging, ACL) is persisted to disk and survives Tarn restarts

## Known Limitations

- Path-style only (no virtual-hosted style: `bucket.s3.amazonaws.com`)
- No actual object versioning (version IDs not tracked; `PutBucketVersioning` stores the setting but object operations don't create version history)
- Server-side encryption config is stored but not applied to stored objects
- Object tagging not persisted (`GetObjectTagging` always returns empty tag set)
- Replication, transfer acceleration, and request payment are accepted as stubs
- Bucket notifications support Lambda targets only
