# UI bug and cleanup audit

Audited on 2026-09-30 at commit `a00a61c`. Scope was `ui/src`, the UI build configuration, and the backend contracts needed to check UI requests. The findings below describe that original audit. Follow-up fixes and validation are recorded first.

The original audit found 14 bugs, including three account isolation problems, and 76 unused files containing 2,229 lines. There are also repeated filtering and section implementations, unused exports, and a large initial page bundle.

## Fixes completed on 2026-10-01

- **B1 fixed.** S3 listing, metadata, content, upload, and delete requests now use the shared account headers and configured API base. Text and image previews use authenticated fetches. Downloads fetch an authenticated blob, and image preview URLs are revoked when the selection changes.
- **B2 fixed.** Account switches clear the overview, cancel the previous load, and start the next load immediately. A generation check prevents late responses, errors, and cleanup from changing the new account's state, including when switching away and back to the same account. Removing the active account uses the same switch path.
- **B3 fixed.** Dashboard sections now remount when either the selected account or tab changes. Logs reload their groups for the new account, and resource panels drop cached environment and secret values. Ordinary polls within one account preserve panel state.

Added 17 regression tests for S3 requests and the real compiled Svelte dashboard state. All 56 UI tests pass, `bun run check` reports zero errors and warnings, and `bun run build` passes. The UI tests now run in CI. Browser checks with synthetic responses confirmed that previews and downloads use the selected account and the configured API prefix. Further fixes are recorded below; the original audit and validation describe the code at `a00a61c`.

The browser regression in [account-panels.browser.js](https://github.com/aircwo-systems/tarn/blob/373af94219d2faf8190c17e41dbc5b2e4e540bc3/ui/src/testing/account-panels.browser.js) failed before B3's fix because Logs kept account A's group list after switching to B. It now passes checks for log groups, environment values, secret values, and preservation of revealed values during an ordinary poll. It exercises the actual dashboard components, intercepts backend requests, and restores account storage. Run it in a dashboard dev-server browser tab:

```js

```

This browser regression runs separately from the Bun tests in CI.

### B1. S3 operations use the default account

Locations: [s3.ts:24](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/s3.ts#L24), [s3.ts:30](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/s3.ts#L30), [object-preview.svelte:43](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/s3/object-preview.svelte#L43). Compare [api.ts:25](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/api.ts#L25) and [account.go:20](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/internal/account/account.go#L20).

The overview uses an Authorization header to select an account. Every S3 helper omits that header. The server therefore resolves listing, HEAD, upload, and delete requests to its configured default account. Image URLs, object downloads, and text preview fetches also omit account selection.

Reproduction selected synthetic account `222222222222`, then called the actual S3 helpers. All four requests had no Authorization header:

```text
GET    /_s3/audit-bucket?list-type=2&delimiter=%2F&max-keys=1000
HEAD   /_s3/audit-bucket/file.txt
PUT    /_s3/audit-bucket/file.txt
DELETE /_s3/audit-bucket/file.txt
```

If the default account has the same bucket name, uploads and deletes affect that bucket. Otherwise, a bucket visible in the selected account can appear missing.

Use the shared account-aware request builder for S3. Fetch image and download blobs with the same account header before creating object URLs. The S3 paths also bypass `VITE_TARN_API_BASE`, so the shared builder must preserve the configured backend address.

### B2. An old overview response can populate the newly selected account

Locations: [state.svelte.ts:131](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/state.svelte.ts#L131), [state.svelte.ts:148](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/state.svelte.ts#L148), [state.svelte.ts:224](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/state.svelte.ts#L224).

`switchAccount` changes the request account immediately but leaves the existing data and request active. `refresh` queues another refresh behind the current one. The current request then assigns its result without checking which account requested it.

Reproduction held account A's overview request, switched to B, released A's response, and held B's response. The observed state was:

```json
{
  "activeAccount": "222222222222",
  "renderedAccount": "111111111111",
  "newAccountRequestStillPending": true
}
```

The UI can show A's resources while new mutation requests use B's credentials. If B's request fails, the stale data remains.

Clear account data at the switch, abort the previous load, and guard response assignment with an account or request generation. Apply the same guard to errors so an old archived-account response cannot change a newer selection.

### B3. Revealed values and local panel state survive account changes

Locations: [+page.svelte:398](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/routes/+page.svelte#L398), [functions-section.svelte:214](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/functions-section.svelte#L214), [function-environment.svelte:9](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/functions/function-environment.svelte#L9), [secrets-section.svelte:215](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/secrets-section.svelte#L215), [secret-detail.svelte:15](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/secrets/secret-detail.svelte#L15).

The page remounts sections only when `activeTab` changes. Function and secret details key their children by resource name. Two accounts with the same names retain the same component instances and their cached values.

Reproduction revealed `AUDIT_VALUE` in account A, switched to B, and completed B's overview refresh. The panel still displayed `SYNTHETIC_ACCOUNT_111111111111`. Only one environment request had occurred, under A. The secret detail has the same name-keyed lifetime and additionally reuses its fetched value after Hide/Reveal.

Include account identity in section/detail lifetimes and invalidate account-specific cached data. Logs also load their groups on mount, so the account boundary needs to cover the whole section, not just revealed values. This issue persists after a successful B response and is separate from B2's request race.

### B4. Pinned logs have no account identity

Locations: [pinned-logs.ts:3](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/pinned-logs.ts#L3), [pinned-logs.ts:11](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/pinned-logs.ts#L11), [pinned-logs.ts:70](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/pinned-logs.ts#L70).

All accounts share `tarn:pinned-logs:v1`. Pin identity includes only the group and event key; the saved record has no account field. Unlike mounted component state, this survives reloads and tab remounts.

Reproduction saved `SYNTHETIC_ACCOUNT_A_PIN` under A, switched to B, then called `readPinnedLogs`. B received A's pin. Identically named groups can show another account's saved lines or fetch context around a timestamp in the wrong account.

Scope storage and pin identity to the account. Keep legacy pins distinguishable when migrating because their original account cannot be inferred from the current selection.

### B5. Links within the current resource tab do not update selection

Locations: [functions-section.svelte:71](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/functions-section.svelte#L71), [api-gateways-section.svelte:72](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/api-gateways-section.svelte#L72), [storage-section.svelte:87](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/storage-section.svelte#L87), [+page.svelte:398](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/routes/+page.svelte#L398).

Most resource sections read their selection from the hash only in `onMount`. The page's hash listener keeps the existing section mounted when only query parameters change.

Reproduction opened `#functions?fn=audit-first`, then changed the hash to `#functions?fn=audit-second`. The URL named `audit-second`; the detail heading remained `audit-first`.

The pattern also appears in ECS, queues, SNS, secrets, triggers, EventBridge, DynamoDB, Step Functions, and services. Browser history or links targeting another resource in the current tab can leave the visible detail inconsistent with the address.

Pass reactive route selection into sections or subscribe through one shared routing mechanism. Preserve drafts when unrelated URL fields change.

### B6. Type filters disagree between sidebar counts and resource tabs

Locations: [+page.svelte:162](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/routes/+page.svelte#L162), [filter-utils.ts:34](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/filter-utils.ts#L34), [functions-section.svelte:24](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/functions-section.svelte#L24), [topology-canvas.svelte:141](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/topology/topology-canvas.svelte#L141).

Sidebar counts and topology recognize tokens such as `lambda` as resource types, then remove those tokens before matching tags. The Functions section sends the complete filter string to `matchesTagFilter`, which treats `lambda` as a tag search.

Reproduction applied `lambda` to two synthetic functions with ordinary tags. The sidebar showed `Functions 2`; the main panel showed `0 functions` and `No functions yet`. Gateway, queue, secret, and SNS sections use the same raw tag-filter pattern.

Use one resource-filter predicate for counts, topology, and lists. Share the type-token parser as well as the tag matcher.

### B7. Clearing all Chaos routes immediately selects them again

Location: [chaos-section.svelte:63](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/chaos-section.svelte#L63).

The initialization effect populates every route whenever `selected.size === 0`. The Clear button and deselecting the final route produce exactly that state, so the effect immediately repopulates the selection.

Reproduction used a gateway with one route and clicked Clear. The panel still showed `1 selected` and `Probe (1)`.

Separate initial selection from an intentional empty selection. Seed once per relevant resource/account load, then prune disappeared routes without selecting everything again.

### B8. Oldest-first live logs repeatedly fetch the oldest page

Locations: [logs-section.svelte:271](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/logs-section.svelte#L271), [logs-section.svelte:367](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/logs-section.svelte#L367).

Live merges reuse the display sort order and deliberately omit the pagination cursor. With `order=asc`, each poll returns the first, oldest page. Once the group exceeds the page limit, newly appended events never reach the merge.

Reproduction started with 201 events, opened Oldest order with the default 200-event page, enabled Tail, and appended an error. After a poll, the UI showed `Live` and `200 of 202 events`, but its range still ended at event 199. Both requests were:

```text
?limit=200&order=asc
```

Fetch the newest events for live merges regardless of display order, or use a separate cursor for events newer than the buffer. Continue sorting the resulting buffer according to the user's display preference.

### B9. A stale folder request overwrites the current S3 listing

Location: [bucket-detail.svelte:38](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/s3/bucket-detail.svelte#L38).

`load` unconditionally assigns its result and has no abort signal or request token. Folder changes can leave several loads active. The `loadedKey` guard prevents duplicate starts but does not protect response assignment.

Reproduction delayed the `folder/` listing, returned to the bucket root, and completed the newer root request. The root correctly showed `new-root.txt`. Releasing the old folder response replaced it with `folder/file.txt`, while the URL and breadcrumb still pointed to the root.

Guard listing, error, and loading assignments with a request generation or captured bucket/prefix identity. Cancel superseded requests where possible.

### B10. Repeated function invocations in one trace are dropped

Locations: [function-links.ts:138](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/function-links.ts#L138), [function-invocations.svelte:32](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/functions/function-invocations.svelte#L32), [function-invocations.svelte:53](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/functions/function-invocations.svelte#L53).

`invocationsFromTraces` uses `findIndex` and emits at most one invocation per trace. Its documented result is function invocations. A trace containing the function twice loses the later duration, status, and downstream calls.

The actual helper received two matching Lambda spans, first successful and second failed. It returned one invocation with status `ok`. That also understates the invocation count and error rate calculated in the function detail.

Emit an entry for each matching span. Give entries an identity containing both trace ID and span position; the rendered lists currently key solely on trace ID. This was verified at the helper boundary, not against a live repeated-invocation workload.

### B11. Event-pattern rule settings cannot be saved

Locations: [eventbridge-section.svelte:117](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/eventbridge-section.svelte#L117), [rule-form.svelte:36](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/eventbridge/rule-form.svelte#L36), [api.ts:561](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/api.ts#L561), [eventbridge service.go:231](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/internal/eventbridge/service.go#L231).

The form accepts an empty schedule as an event-pattern rule. Saving sends `ScheduleExpression: ""`, but neither the UI rule model nor the request includes the existing `EventPattern`. The server requires a schedule or pattern on every PutRule call.

The captured request for a description edit contained an empty schedule and no pattern. The backend contract rejects it with `Either ScheduleExpression or EventPattern is required`; the existing rejection test passed. A synthetic response using that contract also exercised the UI API error path.

Expose the existing pattern in the overview/model and preserve it when updating a pattern rule. Reject creation with neither schedule nor pattern.

### B12. Terraform export does not escape tag keys or string values

Locations: [function-hcl.ts:8](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/function-hcl.ts#L8), [function-hcl.ts:29](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/function-hcl.ts#L29).

The Terraform button wraps values in quotes without escaping their contents and writes tag keys as bare identifiers. Ordinary tag data can therefore produce invalid HCL.

The actual helper exported the tag `team name` with value `He said "hello"` as:

```hcl
tags = {
  team name = "He said "hello""
}
```

`terraform fmt -check /tmp/tarn-ui-audit-terraform.tf` exited 2 with `Missing key/value separator`. The exported file used only synthetic function metadata.

Quote map keys and encode string contents, including quotes, backslashes, newlines, and HCL interpolation sequences. Check exports with Terraform's parser. Provider schema validity was not tested by this reproduction.

### B13. ECS override controls ignore the selected task-definition revision

Locations: [ecs-run-task-dialog.svelte:66](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/ecs/ecs-run-task-dialog.svelte#L66), [ecs-run-task-dialog.svelte:119](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/ecs/ecs-run-task-dialog.svelte#L119), [admin handler.go:1959](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/internal/api/admin/handler.go#L1959), [ecs service.go:516](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/internal/ecs/service.go#L516).

The dialog requests details using `selectedDef.family`, discarding its revision. The backend resolves a bare family to its latest active revision. The launch request nevertheless uses the selected revision's ARN.

Reproduction offered revisions 1 and 2 with different container names. Selecting revision 1 still requested `/_tarn/admin/ecs/task-definitions/audit-task` and displayed `revision-two-container`. The intercepted launch payload combined revision 1's ARN with revision 2's container override name. The runner rejects overrides for a container absent from the selected definition.

Fetch details using `family:revision` or the selected task-definition ARN. Disable launch with overrides until those exact details are loaded. The existing backend revisioning test confirms that explicit revisions and bare families resolve differently.

### B14. ECS command overrides break quoted arguments

Locations: [ecs-run-task-dialog.svelte:111](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/ecs/ecs-run-task-dialog.svelte#L111), [ecs-run-task-dialog.svelte:233](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/ecs/ecs-run-task-dialog.svelte#L233), [runner.go:2330](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/internal/ecs/runner.go#L2330).

The input's own example is `sh -c 'echo hello'`, but the parser splits on all whitespace. It does not recognize quoting.

Entering that example into the real dialog produced this intercepted command array:

```json
["sh", "-c", "'echo", "hello'"]
```

The intended array is `["sh", "-c", "echo hello"]`. The backend passes the supplied array through as the container command, so it cannot repair the split.

Accept an explicit argument array, provide one argument per field, or use a parser with documented quoting rules. Keep the example consistent with the accepted syntax.

## Duplication

### D1. Filtering has multiple competing implementations

[filter-utils.ts](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/filter-utils.ts), [topology-canvas.svelte:136](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/topology/topology-canvas.svelte#L136), and [+page.svelte:165](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/routes/+page.svelte#L165) separately implement type resolution, tag-token extraction, or resource matching. Individual sections then apply only the tag matcher. B6 is the resulting behavior difference.

The local topology parser also has unreachable `case "api gateway"` and `case "secrets cache"` branches because its tokenizer splits on whitespace before the switch. Keep one parser and one resource predicate, then use them everywhere.

### D2. Resource sections repeat their list and selection plumbing

### D3. The utilities path has separate runtime and type implementations

[lib/utils.ts](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/utils.ts) and [lib/lib/utils.ts](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/lib/utils.ts) both define `cn`. ### D4. S3 and Chaos bypass the shared API configuration

[s3.ts](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/s3.ts) and [chaos-section.svelte:160](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/components/sections/chaos-section.svelte#L160) construct root-relative fetches independently of [api.ts:32](https://github.com/aircwo-systems/tarn/blob/a00a61c5d2a1545efea84134cd8837a50516f3af/ui/src/lib/api.ts#L32). A deployment using a separate API origin or prefix can load its overview correctly while S3 and Chaos still contact the dashboard origin. Move backend URL/header construction into a shared client, including streaming requests. End-to-end Chaos account routing also needs the probe runner's outgoing requests checked.
