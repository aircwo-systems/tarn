# Functions completion audit

Audited 14 October 2026 on `develop-mvp` against the [Functions report](functions-deep-dive.md). This covers all seven findings, the two tested performance candidates, metadata caching, and deployment revision work. The report's original probes and measurements remain historical evidence against commit `5f2bd17`.

| Report requirement | Implementation | Regression evidence |
| --- | --- | --- |
| 1. Preserve successful concurrent metadata/code changes and stable lock identity | `Store.mutateFunction`, `commitDeployment`, and lifecycle callbacks serialize complete mutations under the retained function lock. | `TestConcurrentFunctionMutationsPreserveSuccessfulChanges`, `TestStableFunctionLockAcrossDeleteAndRecreate`, `TestDeleteLifecycleFinishesBeforeRecreation`, `TestOldInvocationCannotRecordMetricsOnRecreatedFunction` |
| 2. Allocate and publish layer versions together; failed publication cannot overwrite successful content | Layer-specific locking, staged directory publication, and persisted monotonic sequence preserve the existing version layout. | `TestConcurrentLayerPublishKeepsEveryVersion` checks unique returned versions, matching content/configuration, failed publication, and sequence after deletion/restart. |
| 3. Execute ordered layers through one `/opt` mount | Immutable merged content retains nested paths and executable permissions; later layers win collisions. Injected proxies mount outside `/opt`. | `TestMergedLayersKeepOrderPermissionsAndAttachedContent`; `TestFunctionLayersVersionsUpdatesAndConcurrencyE2E`, including `one local layer` cold/warm execution, two independent modules, and reversed collision order; existing Secrets extension Docker test |
| 4. Validate filesystem-bound names and contain paths across direct and HTTP calls | Parsed references and checked paths reject invalid names, traversal, and storage symlinks; typed invalid-input errors map to HTTP 400. Shared ZIP extraction retains traversal protection. | `TestResourcePathsRejectTraversalAndSymlinks`, `TestFunctionValidationAndConcurrencyHTTP`, existing store ZIP extraction tests |
| 5. Return detached alias and policy responses | Durable metadata operations copy scalar values under the function lock. HTTP encoding operates on detached snapshots. | `TestAliasHTTPResponsesAreDetachedDuringUpdates`, `TestPolicyConcurrentHTTPReadsAndWrites`, `TestVersionsAliasesPoliciesAndConcurrencySurviveRestart` |
| 6. Persist executable published versions, aliases, policies, images, and concurrency reservations | `_tarn` metadata stores snapshots and reservations; parsed qualifiers select immutable deployment/container revisions. Image URI/configuration and resolved image ID persist; busy counts enforce reservations across versions, including zero. Callers retain qualifiers. | `TestVersionsAliasesPoliciesAndConcurrencySurviveRestart`, `TestPublishedVersionsAppearInHTTPListAndQualifiedReads`, `TestImageCreateWithoutRuntimeOrHandlerPersistsImageConfiguration`, `TestImageContainerUsesPinnedImageAndImageDefaults`, `TestNormalizeLambdaFunctionName`; layer/version Docker test and `TestImageFunctionAndPublishedImageVersionE2E` |
| 7. Bound and cancel acquisition, maintain capacity invariants, and avoid missed release notifications | Per-function weighted start gates, cancellable image gates, acquisition deadlines, invocation-context recovery, and availability subscriptions before pool checks | `TestColdStartGateCancellation`, `TestImagePullWaitIsCancellable`, `TestRevisionAcquisitionAndReleaseNotification`; Docker reservation/queued async coverage; `BenchmarkLambdaPoolBurstWait` |
| Count event records outside the metrics lock | `recordInvocationInstance` parses before locking while retaining counting semantics and generation isolation. | `TestCountProcessedMessages`, `TestRecordInvocationAccumulatesMetrics`, old-completion isolation regression; original candidate benchmark artifacts |
| Attempt readiness immediately | `WaitForReady` makes an immediate `DialContext` attempt before subsequent polling, retaining timeout/cancellation. | `TestAlreadyReadyPortDoesNotWaitForPollingTick`, existing readiness and invocation timeout tests |
| Cache metadata without losing disk edits or response isolation | File identity, size, and modification time validate cached records; returned configurations are cloned, listings remain sorted, and restart reloads durable state. Legacy ZIP edits prepare fresh immutable content. | `TestCachedMetadataObservesExternalFileEdits`, persistence/restart and detached-response regressions |
| Prepare and publish revisions atomically, preserve acquired content, and retire safely | Private staged preparation publishes the metadata pointer before mirroring the legacy ZIP. Invocation/container leases retain code and layers until release and confirmed Docker removal. Startup removes unreferenced preparations. | `TestFailedDeploymentRetainsLastWorkingCode`, `TestDeploymentLeaseSurvivesUpdateAndDelete`, `TestRetiredBusyContainerKeepsDeploymentUntilDockerRemoval`, `TestStartupPrunesAbandonedDeploymentsAndKeepsPublishedContent`; running-update/delete Docker coverage |

The completion audit added explicit single-layer Docker execution and startup cleanup tests. The scoped race-enabled suites and both Functions Docker regressions passed after these additions. Final repository gate results are recorded in the [validation record](functions-implementation-validation.txt).

No report requirement remains open. Reservations use the configured local ceiling; weighted aliases, account-wide quotas, IAM authorization, and async retry/DLQ policies are outside the original repair scope. Running invocations finish on their acquired deployment. The implementation was validated on `develop-mvp`; unrelated workspace edits are preserved.
